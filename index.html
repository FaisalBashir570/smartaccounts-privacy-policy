Privacy Policy

Faisal PSP Labs ("we", "us", or "our") develops and operates SmartAccounts, an Android application designed for customer account, ledger, transaction, and business record management.

This Privacy Policy explains what information SmartAccounts handles, how that information is used and stored, when information may be transmitted to our service providers, how backups work, and how users can request account and data deletion.

By using SmartAccounts, users should review this Privacy Policy together with the disclosures presented inside the application.

1. Information We Handle

Depending on the features used and information entered by the user, SmartAccounts may handle the following categories of information:

  • Account information: information used to create and manage a SmartAccounts user account, such as email address, account identifier, role, account status, and related profile information.
  • Customer and business information: customer names, business or shop information, addresses, city or province information, mobile or WhatsApp numbers, and other customer information entered by the user.
  • Financial and accounting information: transaction amounts, sales and recovery records, balances, credit limits, discounts, payment methods, transaction dates, notes, and related ledger information entered by the user.
  • Application information: application settings, preferences, permissions, and other information required to operate the application.
  • Backup information: application records contained in a backup when the user explicitly chooses to create, export, restore, or otherwise use a backup feature.

SmartAccounts does not intentionally collect contacts, photos, audio recordings, location information, SMS messages, call logs, health information, or calendar information for its core functionality.

2. Local and Offline-First Storage

SmartAccounts is designed as an offline-first application.

Customer accounts, ledger records, transactions, and other business records are primarily stored in the application's local database on the user's Android device so that core accounting functionality can continue to operate offline.

Internet connectivity is not required for every normal accounting operation. When a feature requires cloud connectivity, the application communicates with its configured cloud services.

3. Supabase Authentication and Cloud Services

SmartAccounts uses Supabase for authentication, user management, and authorized cloud operations.

Authentication-related information may include the user's email address, account identifier, role, account status, and related profile information.

When authorized cloud synchronization is used, relevant SmartAccounts business records may be transmitted to and stored in the configured Supabase service so that authorized users can use supported cloud functionality.

Cloud synchronization is performed as part of supported, authorized application functionality. It is not a background advertising or behavioral-tracking service.

Supabase processes information on behalf of the application developer according to the services configured for SmartAccounts.

4. Authentication Credentials and Security Tokens

When a user signs in or creates an account, the authentication password is transmitted securely to the configured authentication service for account authentication. SmartAccounts does not store the user's raw account password in its local application database.

SmartAccounts may receive authentication session information, including access and refresh tokens, from its authentication service.

Supported authentication tokens stored locally by the application are protected using Android Keystore-backed encryption. These security tokens are not intentionally included in application backup payloads.

SmartAccounts may also use a local application PIN for local authentication. The PIN is processed locally using a one-way password-based hashing mechanism and is not intentionally transmitted to the cloud service.

5. Backup and Restore

SmartAccounts supports backup and restore functionality for protecting and recovering application records.

Backup operations are initiated by the user or by supported application functionality. Backup data may contain application records necessary to restore SmartAccounts data.

Authentication credentials, raw account passwords, local PIN values, and authentication session tokens are not intentionally included in application backup payloads.

Supported backup data is protected using encryption and authentication mechanisms appropriate to the backup feature.

Users are responsible for protecting any backup files and backup passwords they create or save outside the application.

6. Manual Backup Files

SmartAccounts may allow a user to create a manual backup file and save or share that file using Android's available file-selection or sharing mechanisms.

A manual backup file is created as a result of a user action. Once a user exports or shares a file using Android or another application, that file may be handled according to the privacy practices of the service or application selected by the user.

SmartAccounts does not intentionally use manual backup files for advertising or behavioral profiling.

7. Restore

When a user chooses to restore a backup, SmartAccounts validates the backup and, where required, requests the backup password before restoring supported records to the local application database.

Restoring a backup may replace or update local application records according to the restore operation selected by the user.

8. How We Use Information

Information handled by SmartAccounts is used for purposes such as:

  • Creating and managing SmartAccounts user accounts.
  • Authenticating authorized users.
  • Providing customer and business account management.
  • Recording and displaying ledger and transaction information.
  • Calculating and displaying supported accounting balances and summaries.
  • Providing authorized cloud synchronization functionality.
  • Creating and restoring user-requested backups.
  • Maintaining application security and access controls.
  • Processing account and data deletion requests.

SmartAccounts does not intentionally use customer ledger or financial records for targeted advertising or behavioral advertising.

9. Data Sharing and Service Providers

We do not sell users' personal information.

Information may be processed by service providers when required to provide SmartAccounts functionality. These providers may process information on our behalf rather than using it for their own independent advertising purposes.

Supabase is used for authentication, user management, and supported authorized cloud operations.

Android system services and user-selected applications may also handle information when the user explicitly chooses Android features such as file selection or file sharing.

We do not intentionally sell customer records, ledger information, transaction records, or financial information to third parties.

10. Advertising and Analytics

SmartAccounts is not designed to use customer business or ledger information for targeted advertising.

SmartAccounts does not intentionally collect customer business records for advertising or behavioral profiling.

If this practice changes in a future version, this Privacy Policy and the applicable Google Play disclosures will be updated as required.

11. Data Retention

Local customer accounts, ledger records, transactions, and application settings generally remain on the user's device until they are deleted through the application, the application's data is cleared, or the application is uninstalled, subject to Android device behavior and any user-created copies or backups.

Information stored through authorized cloud functionality may remain in the configured cloud service while the user's account and supported cloud functionality are active, subject to deletion requests and any limited retention that may be required for legitimate security, fraud-prevention, legal, regulatory, or accounting purposes.

User-created backup files stored outside SmartAccounts may remain available until the user deletes them from the location where they were saved.

12. Account and Data Deletion

SmartAccounts provides an in-app account deletion option for eligible user accounts. The deletion process may require re-authentication to help prevent unauthorized deletion.

When an account deletion request is accepted, SmartAccounts is designed to remove the user's local account credentials, local profile information, local authentication/session information, and the applicable SmartAccounts account/profile information maintained through its cloud services.

Users may also request deletion from outside the application, including if they no longer have access to the installed app.

To request account and associated data deletion: send an email to fslmknza@gmail.com with the subject SmartAccounts Account Deletion Request.

Please do not send your password, PIN, authentication tokens, or other security credentials by email.

We will use the information necessary to identify and process the deletion request. Where information must be retained for a legitimate legal, regulatory, security, fraud-prevention, or accounting reason, that information may be retained for the applicable period and handled according to the applicable requirements.

Deleting an account does not automatically delete copies of information that a user has independently exported, shared, or stored outside SmartAccounts, such as manually saved backup files. Users should separately delete those copies when they are no longer needed.

13. Children's Privacy

SmartAccounts is intended for business, customer-account, ledger, and financial record-management use and is not directed specifically to children.

We do not knowingly design SmartAccounts to collect personal information from children for advertising or profiling.

14. Security

We take reasonable technical and organizational measures to protect information handled by SmartAccounts.

Depending on the feature, these measures include:

  • Authenticated access to supported account functionality.
  • Encrypted network communication for supported cloud services.
  • Android Keystore-backed protection for locally stored authentication tokens.
  • One-way hashing and salting for the local application PIN.
  • Encryption and authentication for supported backup data.
  • Access controls and role-based application permissions.
  • Exclusion of authentication tokens and credentials from supported application backup payloads.

No method of electronic storage or transmission can be guaranteed to be completely secure. Users should also protect their Android device, account credentials, PIN, and any exported backup files.

15. Your Choices and Controls

Depending on the feature and account status, users can:

  • Use supported SmartAccounts functionality offline.
  • Choose when to create or restore supported backups.
  • Control information they enter into customer and ledger records.
  • Use the application's account and security controls.
  • Request account and associated data deletion.

Some information is necessary for authentication, account management, or core accounting functionality and may therefore be required to provide the corresponding feature.

We may update this Privacy Policy from time to time to reflect changes to SmartAccounts, its features, service providers, applicable requirements, or our data practices.

When this policy is updated, the new version will be published at this same location with an updated "Last Updated" date.
